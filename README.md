# Axy Issues — Public Issue Tracker

Welcome to the public issue tracker for **Axy**.

This repository is dedicated to:

- 🐛 Bug reports
- 💡 Feature requests
- 💬 General feedback

> **Important:** The Axy source code is private. This repository contains no application source code and exists only to track public feedback and issues.

## Before opening an issue

Please use the appropriate issue form and provide as much useful information as possible.

For bug reports, details such as the app version, Android version, miner model, firmware and version, steps to reproduce, screenshots, and logs can help diagnose the problem much faster.

### 🔐 Do not post sensitive information

Issues in this repository are **public**.

Never include:

- passwords
- wallet private keys or seed phrases
- API keys or credentials
- private tokens
- public IP addresses or private network details you do not want to disclose
- any other personal or sensitive information

If a support request requires sensitive information, please use the private support channel on the Axy Discord server instead of posting it here.

## Issue types

### 🐛 Bug report
Use this when something in Axy does not work as expected.

### 💡 Feature request
Use this to suggest a new feature or an improvement to an existing one.

### 💬 Other feedback
Use this for feedback that does not fit the two categories above.

## Issue workflow

Axy uses a Jira-style workflow:

`To do` → `In analysis` → `Implementing` → `In review` → `In test` → `Closed`

Two additional states are available:

- `Postponed` — valid but deferred.
- `Won't do` — intentionally not planned.

Open workflow states are represented by a single `status:` label. `Closed` and `Won't do` use GitHub's native closed states.

See [WORKFLOW.md](WORKFLOW.md) for the full status definitions and transition rules.
